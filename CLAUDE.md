## What This Is

**EZ Journey** is a B2B SaaS platform (CRM + Sales Pipeline + Project Management) built by EZSoft. UI is in Brazilian Portuguese (pt-BR), code is in English. The app is built with Lovable Cloud and uses Supabase as its backend.

## Architecture

```
Component → Hook (useXXX, TanStack React Query) → Service (Supabase queries/RPCs) → Supabase Postgres
```

- **Pages** (`src/pages/`): Route-level components, all lazy-loaded with `React.lazy()` + `Suspense`
- **Components** (`src/components/`): Organized by feature (admin/, closer/, sdr/, projects/, etc.). UI primitives in `ui/` (shadcn/ui) and `kibo-ui/` (Kibo UI)
- **Hooks** (`src/hooks/`): All data fetching and business logic hooks. TanStack React Query v5 with 30s staleTime, 5min gcTime, no refetchOnWindowFocus
- **Services** (`src/services/`): Business logic layer — Supabase queries and RPCs. Business rules live here, never in components
- **Stores** (`src/stores/`): Zustand for global state (e.g., role simulation)
- **Contexts** (`src/contexts/`): AuthSession, WebPhone, Sidebar

## Key Tech

## Code Conventions

- Use `cn()` from `@/lib/utils` for className composition — never concatenate
- Never hardcode colors — use semantic HSL tokens via `hsl(var(--token))`
- Never use `any` — always explicit TypeScript interfaces
- Memoize lists/rows/cards with `useCallback`, `useMemo`, `React.memo`
- Check Kibo UI (`kibo-ui.com`) first before creating custom components, then fall back to shadcn/ui
- All new components must work in both light and dark mode
- RLS on all new tables, SECURITY DEFINER for cross-role operations, DOMPurify for user HTML

## Critical Business Rules

- **CNPJ Uniqueness (New Business):** Block duplicate CNPJ when active opportunity exists
- **CNPJ Uniqueness (Evolution):** Allow multiple active evolutions for same CNPJ
- **Account Auto-Link:** Triggers create/link Account on Lead insert via CNPJ
- **Lifecycle Progression:** Account lifecycle only upgrades: lead → opportunity → client (never regresses)
- **Head Assignment:** Lucas Oliveira is always Head for all projects
- **Role Round-Robin:** UX/PO, Dev, Treinamento assigned by least-loaded algorithm
- **Won → Active Client:** Trigger inserts into `active_clients` on stage "Ganho"
- **Status Canonical:** Use `'CONCLUÍDO'` (with accent) for completed states

## Role System

Roles: admin, manager, sdr, closer, head_pos_venda, ux_po, dev_chatbot, treinamento, suporte, verificacao_bm. Dual permission system: role-based (`allowedRoles` on routes) + granular permission-based (`permissions` table). `ProtectedRoute` enforces both. Admins can simulate other roles via `useRoleSimulation`.

## Database Patterns

- Server-side pagination via RPCs: `search_leads_paginated`, `search_opportunities_paginated`
- Key RPCs: `get_lead_tab_counts`, `get_opportunity_tab_counts`, `check_cnpj_duplicate_v2`, `get_user_permissions`
- SECURITY DEFINER functions: `transfer_lead_owner`, `has_role`, `is_admin`, `is_manager`, `has_permission`
